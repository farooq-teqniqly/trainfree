# chore(dev): add Aspire AppHost to run the local dev stack with one command

## Problem
Local development needs three terminals (AdminApi Worker on 9999, Blazor dev server on 5280, and optionally IdentityApi on 9998), plus one-time seed and migration steps. Logs are scattered across terminals, and there's no single place to see resource health.

## Proposal
Add a .NET Aspire AppHost project that launches the existing pieces for local dev only:
- `Trainfree.Admin` (Blazor WASM) as a project resource
- `Trainfree.AdminApi` and `Trainfree.IdentityApi` as JavaScript app resources running `npm run dev` (wrangler)

Production is unchanged. Aspire has no Cloudflare Workers/D1 deployment target, so `deploy.yaml` and wrangler remain the deploy path.

## Notes
- Local dev only. Nothing about deployment, wrangler config, or Cloudflare Access changes.
- Wrangler/Miniflare still emulates D1. Aspire does not manage it.
- The Aspire dashboard shows console logs and resource health from these processes. It will not show distributed traces unless the Workers are separately instrumented with OpenTelemetry and pointed at the dashboard's OTLP endpoint. That is out of scope here.
- Windows is the primary dev environment; verify process cleanup on stop, given the known wrangler orphaned-listener issue.

## Acceptance criteria
- A single `dotnet run --project src/Trainfree.AppHost` starts the Blazor client and AdminApi, and optionally IdentityApi, ready for use at the admin UI.
- All three resources show logs and health in the Aspire dashboard.
- Stopping the AppHost leaves no orphaned listeners on 9999/9998/5280.
- The existing manual flow in the README still works.
- CI, hooks, and `deploy.yaml` are unaffected.
