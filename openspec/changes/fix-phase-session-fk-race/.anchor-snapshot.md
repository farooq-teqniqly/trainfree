# Concurrent phase delete + session-phase create can crash with an unhandled FK violation

## Summary

`deletePhase` (`src/Trainfree.AdminApi/src/phases.js:83-96`) and `createSessionPhase`
(`src/Trainfree.AdminApi/src/session-phases.js:32`) each do a separate
check-then-act with no transaction:

- `deletePhase` checks `SELECT 1 FROM session_phases WHERE phase_id = ?` for in-use,
  then `DELETE FROM phases WHERE phase_id = ?`.
- `createSessionPhase`'s caller (`handleSessionPhasesCollection`,
  `src/Trainfree.AdminApi/src/index.js:333`) checks `phaseExists` before inserting the
  new `session_phases` row.

If a phase-delete and a session-phase-create for that same phase interleave, the
existence checks can both pass before either write lands, and the losing write hits
`session_phases.phase_id REFERENCES phases(phase_id)`'s FK constraint
(`migrations/0012_create_session_phases.sql:6`), which is currently unhandled and
surfaces as a `500` instead of the documented `400`/`409`.

## Where this came from

Flagged as an open question by the adversarial review on PR #88
(`docs/pr-reviews/PR_REVIEW_88.md`) and independently confirmed by Qodo's automated
review on the same PR ("Concurrent edits return server errors").

## Decision needed

This is a single-user app (per `CLAUDE.md`), so the race window is narrow and the
practical odds of hitting it are low. Two ways to close it if we want to:

1. Wrap the check-and-write in a D1 `db.batch` so it's atomic.
2. Catch the FK constraint violation at the point of insert/delete and translate it to
   the documented `400`/`409`, instead of preventing the race itself.

Option 2 is the smaller change and directly fixes the "500 instead of 400/409" symptom
without a broader transactional rework.

## Acceptance criteria (if fixed)

- A concurrent `POST .../phases` (create session phase) racing a
  `DELETE /api/phases/:id` for the same phase never surfaces as an unhandled `500`.
- Add a test exercising the FK-violation path directly (not just the happy-path
  check-then-act) for both directions (delete-wins, create-wins).
